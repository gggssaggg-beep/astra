## Чем эталон отличается от нашей реализации (подозреваемые)

1. **Иконка.** У нас: кастомный vector `ic_stat_astra` + `iconColor` в
   `capacitor.config.ts`. У MENS: ничего, системный дефолт. Кривая/неугодная
   прошивке иконка — один из немногих способов «notify() прошёл, а уведомления
   не видно». XML синтаксически корректен, но подозреваемый №1 → в новой
   реализации иконку НЕ задавать НИГДЕ (ни в config, ни в вызовах).
2. **Каналы.** У нас: два канала, importance 4 и 5, свет/вибро/visibility.
   У MENS: ОДИН канал, importance DEFAULT (3), `vibrationPattern [0,120]`.
   → один канал `care` («Напоминания»), importance 3, vibration true, больше
   ничего.
3. **Тихие отказы.** У нас `catch {}` глотали всё → отладка вслепую. В новой
   реализации КАЖДЫЙ шаг оставляет след (см. «журнал шагов» ниже).

## Фаза 1 — новый модуль `app/src/lib/reminders.ts` (порт принципа MENS)

Структура — зеркало `C:\purba\MENS\src\notifications\reminders.ts`:

- `ensureInit()`: идемпотентно (флаг в модуле); создаёт ОДИН канал
  `{ id: 'care', name: 'Напоминания', importance: 3, vibration: true }`.
- `granted()` / `requestPermission()`: сначала `checkPermissions()`; если уже
  granted — `requestPermissions()` НЕ звать (грабли: повторный запрос при
  выданном разрешении зависал на части устройств).
- `rescheduleAll(cfg)`: снять наши id (фиксированный диапазон 1000..1099,
  чужие не трогать) → поставить включённое заново. Идемпотентно. Зовётся на
  старте ПОСЛЕ движка и при каждом изменении настроек уведомлений/пояса/орбиса.
  Нет разрешения — выйти тихо, но записать это в журнал шагов.
- Ежедневная сводка: `schedule: { on: { hour, minute } }`. Время задано в
  ПОЯСЕ приложения, а плагин повторяет по часам телефона — перевод через
  `zonedDayStartUTC(todayCivil(tz), tz)` (см. `lib/format.ts`; готовая логика
  есть в git-истории удалённого notifications.ts — `git show HEAD:app/src/lib/notifications.ts`).
- Аспекты: одноразовые `schedule: { at, allowWhileIdle: true }`, только
  будущее время с запасом ≥60 с (грабли: момент «в прошлом» натив МОЛЧА
  выбрасывает, JS получает успех), скан ~10 дней, без Луны, лимит диапазона id.
  Тяжёлый WASM-скан — с передышками `await new Promise(r=>setTimeout(r,0))`
  и «номером поколения», чтобы устаревший проход не побеждал свежий
  (обе заготовки есть в git-истории).
- `sendTest()`: МГНОВЕННОЕ уведомление БЕЗ `schedule` (прямой notify — мимо
  AlarmManager) + второе через 10 с (`allowWhileIdle`). НЕ 1.5 с (см. грабли).
- Все нативные вызовы — через `withTimeout(промис, мс, 'имя шага')`
  (перенести из git-истории), чтобы зависший мост давал понятную ошибку.
- **Журнал шагов** — ключевое новое требование: модульный массив
  `log: string[]` (последние ~30 записей: «плагин загружен ✓», «разрешение:
  granted», «канал создан ✓», «schedule(2 шт) ok», «ОШИБКА шага X: …»).
  Каждая публичная функция пишет туда. Экспорт `reminderLog()`. Никаких
  пустых `catch {}` — минимум `log.push(...)`.

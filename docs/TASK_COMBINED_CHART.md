## Ключевое отличие от текущего движка

Сейчас Astra считает аспекты как ИНТЕРВАЛ во времени (вход→точно→выход) для
ОДНОГО неба на момент. Натальная/синастрическая/композитная карта —
**статичный снимок** (фиксированные долготы), аспект = просто разница углов на
этот момент, без окна. Значит нужны новые «статичные» функции аспектов, не
переиспользуя транзитные `aspectsOn`/`AspectRecord` (там beginTime/endTime).

## Модель данных — «человек» (готова к домам)

Новая коллекция в `lib/db.ts` (`people`), входит в export/import и durable-save.
Поля СРАЗУ включают время и место (для домов позже), но они опциональны:

```ts
interface Person {
  id: string;
  name: string;
  birthDate: string;        // 'YYYY-MM-DD' (гражданская дата рождения)
  birthTime: string | null; // 'HH:MM' или null = время неизвестно
  birthTz: string;          // IANA пояс МЕСТА рождения (для перевода в UTC)
  place: { name: string; lat: number; lon: number } | null; // нужно для домов
  unknownTime: boolean;     // true → берём полдень (12:00), Луна/дома неточны
  createdAt: string;
}
```

- **Момент рождения (UTC)** = `zonedDayStartUTC(birthDate, birthTz)` + время
  (при `unknownTime` — 12:00 пояса рождения). Логика перевода уже есть в
  `lib/format.ts`.
- Место для домов: пока поле опционально. Ввод координат — вручную (широта/
  долгота) ИЛИ маленький встроенный список городов (оффлайн; геокодинг по сети
  НЕЛЬЗЯ). Для v1 без домов место можно не заполнять.

## Расчёт (новый модуль, напр. `engine/relationship.ts` или `lib/charts.ts`)

Позиции натала = уже существующий `engine.positions(instantUTC)` — движок считает
на любой момент, менять его НЕ надо.

- `natalPositions(engine, person): BodyPosition[]` — обёртка (момент из person).
- **Синастрия** — межаспекты между двумя наборами:
  `synastryAspects(posA, posB, orbOf): CrossAspect[]` — для КАЖДОЙ пары
  (a из A) × (b из B), включая одноимённые (A.Солнце–B.Луна и т.п.), проверить
  разницу долгот против углов ASPECTS; орбис пары — БОЛЬШИЙ из orbOf(a),orbOf(b).
  `CrossAspect = { a: string; b: string; aspect; symbol; orb; tone }` (без
  времени — снимок). Порядок вывода — по удалённости от Солнца, как в транзитах.
- **Композит** — карта средних точек:
  `compositeChart(posA, posB): BodyPosition[]` — для каждого объекта КРУГОВАЯ
  средняя точка долгот (по КОРОТКОЙ дуге: `mid = normalize(lonA + signedDelta/2)`,
  где signedDelta = кратчайшая разница lonB−lonA в (−180,180]). Затем
  `staticAspects(posMid, orbOf): StaticAspect[]` — аспекты ВНУТРИ одного набора
  (пары i<j, разница углов vs ASPECTS). Тот же StaticAspect используем и для
  «просто натальной карты» одного человека, если понадобится.

Тон аспекта (гармоничный/напряжённый/нейтральный) — из существующего
`aspectTone` (lib/format.ts).

## UI

Вход: в Библиотеке новый пункт «Совмещённые карты» (или отдельная шторка).
- **Люди**: список + форма добавить/править/удалить (имя, дата, время +
  тумблер «время неизвестно», место — опционально: координаты или город).
- **Карта**: выбрать двух людей → переключатель **Синастрия / Композит** →
  - колесо: для синастрии ДВА кольца (внешнее — B, внутреннее — A) + линии
    межаспектов; для композита ОДНО кольцо. Расширить `ui/Wheel.svelte`
    (двойное кольцо + набор линий по CrossAspect); переиспользовать signIcons,
    глифы, палитру тонов.
  - список аспектов под колесом — строки в духе AspectCard, но СТАТИЧНЫЕ
    (глиф-аспект-глиф, имена участников, орбис; без вход/точно/выход). Можно
    сделать облегчённый `StaticAspectRow.svelte`, не трогая транзитный AspectCard.
- Позиции — в знаке+градусе (`fmtPos`), не сырой долготой.

## Осторожно / решения на подумать

- Орбисы синастрии обычно уже транзитных — для v1 берём `orbResolver`, вопрос
  отдельных орбисов пары вынести в настройки позже.
- Неизвестное время → полдень; помечать в UI, что Луна (≈13°/сут) и дома неточны.
- Композитная средняя точка Луны/быстрых — следить за круговой дугой (не
  арифметическое среднее!), иначе точка «через 0° Овна» уедет на 180°.
- Не плодить сущности: статичные аспекты — свой лёгкий тип, транзитный
  `AspectRecord` не переиспользовать (там временные окна, которых тут нет).

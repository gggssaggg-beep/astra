## 1. «Сканер геометрической избыточности» — конфигурации аспектов ★ключевое

Идея: не просто аспекты, а ФИГУРЫ (скрытая геометрия). В натале — классика;
изюминка владелицы — ТРАНЗИТЫ: фигура, собирающаяся из транзитных аспектов
(или транзит, ЗАМЫКАЮЩИЙ натальную заготовку — напр. транзитная планета к
натальной оппозиции = Тау-квадрат), выделяется как многоплановое событие —
«динамика и вау-обстоятельства».

Архитектура (ложится на существующий движок идеально):
- Фигура = набор рёбер-аспектов. Аспект в приложении — ИНТЕРВАЛ, значит
  **окно жизни фигуры = пересечение интервалов всех её рёбер** (вход
  последнего ребра → выход первого). Философия «аспект-окно» сохраняется.
- Реестр фигур — data-driven (как ASPECTS): { имя, арность, маска рёбер }.
  v1: Большой трин (3×△), Тау-квадрат (☍ + 2×□ к вершине), Большой крест
  (2×☍ + 4×□), Парус/Змей (Большой трин + ☍ к вершине + 2×⚹).
  **У владелицы спросить её полный список и определения** («Повозка» — какие
  аспекты/сколько планет; терминология школ различается) — реестр расширим.
- Поиск: перебор комбинаций объектов по маске (C(11,3)=165, C(11,4)=330 —
  дёшево); режимы: натал (снимок static.ts), транзит×транзит (день), и
  смешанный транзит×натал в картах (транзит достраивает фигуру — самый «вау»).
- UI: полигон фигуры в колесе (подсветка всех рёбер разом), карточка фигуры
  в дне с окном сборки; опц. уведомление «собирается Тау-квадрат».
- Название в UI — обсудить: «сканер геометрической избыточности» (рабочее),
  человеку понятнее «Фигуры неба» / «Геометрия дня».

## 2. Цепочки диспозиторов (формула — готова)

Формула детерминированная, ИИ для построения НЕ нужен (нужен только для
трактовки): **каждая планета → управитель знака, в котором она стоит**
(система владелицы = `SIGN_RULER` в `dispositorLore.ts`), повторять, пока не
придём к планете в СВОЁМ знаке (финальный диспозитор, «царь цепочки») или к
циклу взаимной рецепции (соправители). Солнце/Луна/Раху/Кету ничем не
управляют → они всегда истоки стрелок, в них никто не «впадает»; в графе
максимум 6 узлов-управителей (Марс, Венера, Меркурий, Юпитер, Сатурн, Уран).
- Расчёт тривиален по natal-позициям; визуализация — цепочка глифов
  «X → Y → Z ⟲» или дерево.
- Трактовка композиционная: ребро «архетип X служит архетипу Y (бога знака)»,
  финал — «вся карта стекается к Z». Промт для ИИ-чата: перечислить цепочку
  богами + попросить бытовой разбор «кто на кого работает».

## 4. Аспекты планет к куспидам домов — движковая часть

Сейчас: куспиды СЧИТАЮТСЯ (swe_houses, 10 систем, в колесе карт), но аспекты
к ним НЕ считаются нигде, орбисов у куспидов нет. Сделать:
- Куспид = точка; аспект планета→куспид той же математикой разницы долгот

  планета×куспид — больший из двух). Куспиды движутся ~1°/4мин реального
  времени рождения — предупреждение при неточном времени (unknownTime →
  дома и так отключены, slowOnly).
- Показ: в карточке карты список «аспекты к куспидам» + трактовка из блока F
  (`planetCuspLore.ts`) — контент уже будет готов в раунде 28.

## 5. Поиск планеты в градусе («Венера в 27°56′ Льва, 2020–2030»)

Возможно, и точно: целевая долгота = знак×30 + градус + минуты; сканер шагает
по эфемеридам и уточняет корень (та же техника root-finding, что для точных
аспектов). Планета может проходить точку 1 или 3 раза за цикл (директ-ретро-
директ) — выдаём ВСЕ прохождения с датой и временем в поясе пользователя.
Диапазон лет любой в пределах файлов эфемерид. UI: мини-инструмент «Поиск
градуса» (планета, знак, градус°минута′, годы от/до → список дат; тап по
дате → открыть день). Дёшево: один новый модуль движка + маленькая шторка.

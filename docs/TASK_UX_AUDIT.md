# TASK_UX_AUDIT.md — аудит UX на избыточность (бриф для Fable)

> Бриф для Fable (архитектор). **Исследовать и спроектировать, не писать код.**
> Fable читает это + `CLAUDE.md`, изучает интерфейс, выдаёт аудит + пошаговое
> задание для дешёвых моделей + PR с документом `docs/UX_AUDIT.md`. Правила:
> оффлайн-первый, «ты», авторские тексты/архетипы НЕ трогать, «сам элемент, не рамка».

## Цель (слова владелицы)
Проанализировать интерфейс: **есть ли избыточные моменты? можно ли убрать что-то
лишнее?** Упростить, не потеряв нужного.

## Главное ограничение — минимум потерь
Владелица дорожит богатством функций (аспекты-окна, фигуры, диспозиторы, ретро-фазы,
куспиды, синастрия, карты, библиотека трактовок). **Астрологические ВОЗМОЖНОСТИ не
вырезать.** Аудит — про ВИЗУАЛЬНУЮ и навигационную избыточность и ясность, а не про
удаление фич. Когда сомневаешься — предлагай **прогрессивное раскрытие** (спрятать
продвинутое за тап/аккордеон), а не удаление.

## Что искать
1. **Дубли информации** — одно и то же показано в нескольких местах (напр. значения,
   которые повторяются в шапке, карточке и шторке).
2. **Перегруженные экраны** — слишком много одновременно; что можно свернуть/убрать
   с глаз до запроса.
3. **Редко нужное, что шумит** — элементы, которые видны всегда, а нужны редко.
4. **Навигационное трение** — лишние тапы, неочевидные входы, разные пути к одному.
5. **Непоследовательность** — разные паттерны для похожих действий (кнопки, шторки,
   отступы, заголовки).
6. **Мёртвые/полузаброшенные места** — то, что осталось от прошлых раундов и уже не
   несёт смысла.

## Ориентиры по коду (откуда начинать смотреть)

- Хаб карт: `ui/ChartsSheet.svelte` (транзит+натал / синастрия / тройной / натал —

  `DegreeSearchSheet`, `Interpretations*`) — не дублируются ли входы/разделы.
- Нижнее меню: Библиотека · Карты · Сообщество · Настройки.
- Настройки: `ui/DataPanel.svelte` (только что упорядочены в 6 разделов —
  проверить, не осталось ли лишнего).
- Колесо: `ui/Wheel.svelte` (сколько всего рисуется одновременно, не мешает ли).

## Что выдать (`docs/UX_AUDIT.md`)
1. **Таблица находок:** элемент (файл:строка) → проблема (дубль / перегруз / шум /
   трение / непоследовательность) → рекомендация (**убрать / объединить / свернуть
   за прогрессивное раскрытие / оставить**) → что теряем, если тронуть.
2. Приоритизация: сначала дешёвые победы с явным выигрышем в ясности.
3. **Пошаговое задание для дешёвых моделей** мелкими партиями (по 3–4 правки),
   каждый шаг проверяем `svelte-check` + `npm run build`, с критерием приёмки
   «функция не потеряна, экран стал спокойнее».
4. Явный список того, что трогать НЕЛЬЗЯ (авторские тексты, движок, ключевые фичи).

## Рамки
- Ничего не удалять из астрологической логики и контента.
- Уважать «сам элемент, не рамка», оффлайн-первый, тему/эстетику «живого стекла».
- Предпочитать сворачивание удалению; любые «убрать» — с явным обоснованием.

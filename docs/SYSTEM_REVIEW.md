# SYSTEM_REVIEW.md — системное ревью Astra (2026-07-10)

> Аудит архитектуры и тех-долга. **Код не менялся** — только этот документ.
> Прогон локальный (Fable), все находки проверены по живому коду с `файл:строка`,
> не по памяти. Здоровье на момент ревью: `svelte-check` **0 ошибок / 0
> предупреждений (368 файлов)**; чистые Node-тесты зелёные (статика 20/20,
> фигуры 51/51, тихое время 14/14). Смежный аудит UI-избыточности — PR #1
> (`docs/UX_AUDIT.md`); его находки здесь НЕ дублируются, только референсы.

## Резюме (5–10 строк)

Архитектура **здоровее, чем обычно бывает у проекта такого темпа** (29 раундов
за две недели). Ключевой контракт ЗАДАНИЕ §2.3 соблюдён строго: движок — чистый
слой без единого импорта из `lib/`/`ui/`, WASM заперт в `engine/engine.ts` за
синглтоном `engineStore`, весь доступ — через баррель `engine/index.ts`. Слой
данных дисциплинирован (обёртка+`payload()` централизованы в `db.ts`, `.slice()`
для Svelte 5 — везде, где реактивно). Мёртвых модулей нет — у всех 98 файлов
есть импортёры. Главные проблемы НЕ в коде приложения, а вокруг него:
**(1) OTA-бандл бесконечно копит старые сборки** — баг одной строки CI, из-за
которого владелица качает 28 МБ вместо ~15 и «OTA рвётся»; **(2) слот-логика
уведомлений не покрыта тестами** (заперта за Capacitor-импортом);
**(3) `ChartsSheet.svelte` разросся до 1185 строк** — единственный настоящий
god-компонент.

## Находки

### 🔴 SR-1. OTA-бандл копит ВСЕ прошлые сборки — качается втрое больше нужного

**Где:** `.github/workflows/build-apk.yml:88` →
`(cd app/dist && zip -r -q ../../apk/bundle.zip .)`

**Факт (проверено):** внутри `apk/bundle.zip` сейчас **891 файл, 83.7 МБ
распакованных** — в том числе ~10 поколений хэшированных `assets/index-*.js`
по 1.76 МБ каждое (таймстампы одного дня с 17:41 до 00:22). Свежий `dist`
содержит одно поколение.

**Механизм:** `apk/bundle.zip` закоммичен в репо → CI чекаутит его → `zip -r`
в СУЩЕСТВУЮЩИЙ архив **дописывает/обновляет**, но не удаляет: у vite-ассетов
уникальные хэш-имена, поэтому старые никогда не перезаписываются и копятся
вечно. Каждый прогон CI зип растёт на ~2 МБ.

**Влияние:** каждое OTA-обновление тянет ~28.6 МБ вместо ~15 (из которых 12 —
эфемериды, см. SR-2). Жалоба «OTA рвётся (13МБ)» — прямое следствие; растёт и
git-история (каждый коммит CI несёт зип целиком).

**Рекомендация (фикс одной строкой):** перед упаковкой удалить старый архив —
`rm -f apk/bundle.zip` в начале шага, либо `zip -FS -r` (filesync — удаляет из
архива то, чего нет на диске). Проверка: после следующей сборки
`unzip -l apk/bundle.zip` показывает ОДНО поколение `index-*.js` и ~15 МБ.

### 🟡 SR-2. 12 МБ эфемерид едут в каждом OTA, хотя не меняются

**Где:** `wasm/swisseph.data` (12.08 МБ) внутри `bundle.zip`; воркбокс уже
кэширует его рантаймом (`vite.config.ts` → `runtimeCaching` CacheFirst).

**Влияние:** даже после фикса SR-1 каждое OTA ≈ 15 МБ, из них 12 — неизменный
файл данных.

**Рекомендация:** НЕ трогать сходу — Capgo заменяет веб-папку целиком, и без
`wasm/` внутри бандла движок останется без данных. Возможные пути (исследовать
отдельно, с проверкой на устройстве): (а) грузить `swisseph.data` не из бандла,
а по URL с CacheFirst-кэшем (уже настроен) — тогда OTA ≈ 3 МБ; (б) остаться
как есть — работает, цена известна. **Требует проверки владелицей** — рисковая
зона (офлайн-первость критична).

### 🟡 SR-3. Слот-логика уведомлений не тестируема — заперта за Capacitor

**Где:** `lib/reminders.ts` (372 строки) — статический импорт
`@capacitor/local-notifications` (намеренный: динамический `import()` висел в
офлайн-WebView, корень бага 2026-07-04 — НЕ откатывать).

**Влияние:** самая хрупкая бизнес-логика приложения — раскладка аспектов по
слотам сводок (once/twice, вечерняя забирает ночные), ID-диапазоны
(1000..1029/1030..1129/1130..1229), вставка ретро-станций — живёт в модуле,
который не грузится в Node, и не покрыта ни одним тестом. Прецедент решения
уже есть: `lib/quiet.ts` вынесен из reminders ИМЕННО по этой причине и получил
тест 14/14.

**Рекомендация:** повторить приём quiet.ts — вынести чистые функции
(разбиение аспектов по слотам, выбор слота для станции, распределение ID) в
`lib/digestSlots.ts` без импортов Capacitor + `test/digest.mjs`. reminders.ts
останется тонкой обвязкой над плагином. Риск низкий (перенос без изменения
логики), выигрыш — страховка самой жалобной подсистемы.

### 🟡 SR-4. `ChartsSheet.svelte` — god-компонент (1185 строк, ~8 обязанностей)

**Где:** `ui/ChartsSheet.svelte` — в одном файле: 4 режима карт, CRUD людей и
форма с масками ввода, скраб транзита с масштабами (`:156-209`), дома+куспиды,
фигуры, прогноз, генерация ИИ-промптов, «когда ещё» (anchor). Для сравнения:
весь движок (`engine/`) — ~1200 строк на 10 файлов.

**Влияние:** каждая правка любого режима компилирует/рискует всем файлом;
новые фичи карт (дома фазы 3) продолжат его раздувать. При этом ВНУТРИ файл
дисциплинирован (комментарии-обоснования, `$derived`-цепочки аккуратные) —
это долг размера, не качества.

**Рекомендация (постепенно, по одному куску за партию):** вынести
самодостаточные блоки: `PersonForm.svelte` (форма+маски, ~150 строк),
`TransitScrub` (скраб+масштабы+Intl-кэш `:156-209`), `PeopleList.svelte`
(список выбора). НЕ трогать реактивное ядро расчётов (posA/posB/дома) — оно
переплетено осознанно. Смежное: UX_AUDIT #14–#16 (PR #1) — общие подкомпоненты
шторок трактовок и `libSheet` в App.svelte.

### 🟡 SR-5. `engine/events.ts` — единственный модуль движка без теста

**Где:** `engine/events.ts` (111 строк — ингрессии, станции, фазы Луны для
ленты дня). Покрытие остального движка: engine.ts+aspects (parity),
figures 51/51, static 20/20, retro, degreeSearch, aspectSearch, dispositors,
cuspAspects, quiet — у всех свои прогоны (`app/package.json` scripts).

**Влияние:** «События дня» и дайджест-станции опираются на непокрытый код;
регресс заметят глазами, не CI.

**Рекомендация:** `test/events.mjs` по образцу `retro.mjs` (там же паттерн
проверки станций Меркурия янв/фев 2022) — известные ингрессии/фазы пары дат.
Также без тестов: `lib/forecast.ts`, `lib/chartFigures.ts` (чистый — тест
дёшев), `lib/dayCache.ts` (тянет Engine/WASM — принять как есть).

### 🟢 SR-6. Широкий интерфейс `Wheel.svelte` — фиксировать, не чинить

**Где:** `ui/Wheel.svelte` (401 строка) — пропы транзитного режима + двойного
кольца (`positionsOuter`/`staticAspects`/`selectedStaticKey`/`onstatictap`) +
фигур (`figureSigs`/`figureStaticKeys`) + скраба (`onscrub`).

**Влияние:** интерфейс колеса растёт с каждой фичей; пока управляемо (все
пропы опциональны, транзитный режим не тронут синастрией — проверено раундом
синастрии). Дробить на два компонента = дублировать SVG-геометрию — хуже.

**Рекомендация:** оставить; при следующем крупном пропе — сгруппировать
опции в объект `rings?: {...}` вместо новых плоских пропов.

### 🟢 SR-7. Шрифты: 12 пакетов @fontsource в бандле всегда

**Где:** `lib/fonts.ts:11-21` (10 семейств статикой) + `main.ts:1-11`
(Space Grotesk/JetBrains/Unbounded). Значительная часть из 891 файла бандла —
woff2-субсеты.

**Влияние:** вес `dist` (не рантайма: `unicode-range` — браузер тянет только
нужные субсеты; в APK/OTA лежат все). Осознанный офлайн-трейдофф, задокументирован
в самом файле.

**Рекомендация:** оставить. Если после SR-1/SR-2 OTA всё ещё «рвётся» —
кандидат на диету №1: оставить 4–5 самых используемых семейств.

## Что подтверждено ЗДОРОВЫМ (проверял, не нашёл проблем)

- **Чистота движка:** в `engine/` ноль импортов из `lib/`/`ui/` (grep пустой);
  `swisseph-wasm` упоминается только в `engine/engine.ts:8` и комменте
  `engineStore`. UI получает `Engine` пропом, типы — type-only импортами.
- **Контракт §2.3:** весь доступ через баррель `engine/index.ts` (16 строк,
  явный публичный интерфейс).
- **Слой данных:** обёртка `{app,schema,savedAt,data}` читается ТОЛЬКО через
  `payload()` (`db.ts:52`), все три читателя внутри db.ts; `flushNow()` перед
  OTA; дебаунсы файл/Preferences разделены.
- **Svelte 5 дисциплина:** все реактивные `db.x.all()` — со `.slice()`
  (27 использований проверены; без slice — только одноразовые чтения в
  `chat.ts:39` и `find()`-проверки).
- **Мёртвого кода нет:** у каждого из 98 модулей есть импортёры (включая
  мелочь `telegram.ts`/`push.ts`/`signature.ts`). `compositeChart` —
  законсервирован НАМЕРЕННО (CLAUDE.md), не считается.
- **Направление зависимостей:** `lib/` не импортирует из `ui/` (grep пустой).
- **Кэш горячего пути:** `lib/dayCache.ts` (75 строк) снимает WASM-пересчёты
  при свайпах; Intl-форматтеры кэшированы в скрабе (`ChartsSheet:159-170`).

## Что НЕ трогать (осознанные решения, не долг)

- **Авторские раскладки**: боги на планетах (`lib/lore.ts`, LORE_VERSION),
  управители знаков системы владелицы (Рак→Меркурий, Козерог→Уран) — замысел.
- **`compositeChart`** в движке без UI — законсервирован до натала.
- **Статический импорт Capacitor-плагинов** (reminders, preferences, haptics) —
  лекарство от зависания динамического `import()` в офлайн-WebView.
- **Вшитые не-секреты**: Supabase URL+publishable key (`lib/community.ts`,
  RLS защищает), debug-keystore в репо (sideload-подпись, стабильность
  обновлений). Ключ Anthropic — только в `lib/secret.ts`-хранилище, в коде/
  гите не найден (проверено).
- **Один JS-чанк ~1.76 МБ без code-splitting** — для офлайн-приложения,
  раздаваемого локально Capacitor'ом, дробление не даёт выигрыша.
- **`static.ts` ≠ `aspects.ts`** (снимок vs интервал) — параллель осознанная,
  у них разные модели данных (`StaticAspect` без окна), не «дубль».

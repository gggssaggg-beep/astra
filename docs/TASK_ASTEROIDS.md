# ЗАДАНИЕ: доп. объекты (астероиды) по тумблеру

Команда владелицы 2026-07-27: «делай астероиды по тумблеру», тексты — агентами.
Замысел был записан в CLAUDE.md давно («ДОП. объекты: Хирон/Фолус/Церера/Паллада/

## Что уже есть (проверено)

- **Файл эфемерид астероидов УЖЕ в бандле приложения.** В `app/public/wasm/
  swisseph.data` (12 МБ) лежат ровно три файла: `sepl_18.se1`, `semo_18.se1` и
  **`seas_18.se1`** — последний и есть астероиды (Хирон, Фолус, Церера, Паллада,
  Юнона, Веста). Докачивать нечего, APK не потяжелеет.
- Движок зовёт `swe.calc_ut(jd, code, flag)` с `FLAG_SWIEPH` — любой код объекта
  сработает без правок движка.
- UI объектов: чипы в `ui/DataPanel.svelte` (список `ORB_OBJ`, строки 14–15) —
  используется ДВАЖДЫ: тумблеры объектов и настройка орбисов.
- Деградация тестов текста: `pairLore`/`pairAspectLore` в комментариях честно
  помечают доп. объекты как «добор позже», при отсутствии пары UI не падает.

## Чего нет

`engine/constants.ts`: в `BODIES` только 9 базовых объектов; в `SWE_CODE` нет
кодов астероидов; в `PLANET_GLYPH` нет их глифов; в `SUN_RANK` нет порядка.
`ORB_OBJ` в DataPanel захардкожен на 11 имён.

## Ф1 — механика (одна партия дешёвой моделью)

Коды Swiss Ephemeris: Хирон 15, Фолус 16, Церера 17, Паллада 18, Юнона 19,
Веста 20, Лилит (средний апогей Луны) 12.

Глифы Unicode (блок U+26B3–U+26B8, шрифт `.glyph` = Segoe UI Symbol / Noto Sans
Symbols2): Церера ⚳, Паллада ⚴, Юнона ⚵, Веста ⚶, Хирон ⚷, Лилит ⚸.
**Фолус — в v1 НЕ включаем: у него нет общепринятого символа в Unicode**, на
телефоне будет «тофу»-квадрат. Вернуть, если владелица попросит (тогда нужен
парный SVG-глиф, а решение по глифам планет — Unicode, см. память).

- Все новые объекты **по умолчанию ВЫКЛЮЧЕНЫ** (`Settings.objects` не меняем для
  существующих пользователей — иначе у людей внезапно поедут колесо и сводка).
- `SUN_RANK`: астероиды после базовых (значения > базовых, но < 99), порядок:
  Хирон, Церера, Паллада, Юнона, Веста, Лилит.
- `DEFAULT_ORBS` (lib/models.ts): для доп. объектов орбис **0.5°** — они мелкие,
  на 1° засорят сводку.
- Проверить, что НЕ ломаются: цепочки диспозиторов (астероиды не управляют
  знаками — их в цепочки не пускать), детектор фигур, прогноз транзитов,
  промпт для ИИ (подтянутся сами через список объектов).
- Тесты: `npm run test:static`, `test:parity`, `test:figures` — зелёные;
  `npm run check` и `build`.
- **Проверка на устройстве обязательна:** глифы ⚳⚴⚵⚶⚷⚸ могут не найтись в шрифте
  Android WebView. Если «квадратики» — фолбэк `PLANET_GLYPH[o] ?? '•'` уже есть,
  но лучше показать владелице скриншот до отгрузки.

## Ф2 — тексты (партиями, дешёвыми моделями, ПОСЛЕ Ф1)

Корпус писался под 11 объектов; каждый новый объект даёт пары со всеми
остальными × 5 аспектов. Дробить строго по файлам и партиями по 1–2 объекта
(лимиты рвут крупные генерации):

1. `lib/lore.ts` → `PLANET_LORE`: архетип каждого нового объекта (роль + миф +
   блок «На практике…», как у планет; LORE_VERSION поднять → migrateLore
   перезальёт на устройства).
2. `lib/pairLore.ts` → смысл пары «объект × объект» для новых сочетаний.
3. `lib/pairAspectLore.ts` → уникальные тексты «пара × аспект» (самый объём).
4. `lib/transitSelfLore.ts` → фазы цикла для транзита объекта к своей же точке.
5. Глоссарий `lib/glossary.ts` — статья «Астероиды» + чип «?» в блоке «Объекты»
   Настроек. **Проверить достижимость** скриптом (см. память
   `astra-glossary-orphan-trap` — 9 из 40 статей были мёртвыми).

Правила текстов: на «ты», бытовым языком, авторскую раскладку богов НЕ трогать,
в транзите не писать «про характер» (урок TRANSIT_FEEL).

**Запрещено писать:** что Лилит — планета, астероид или спутник (частая

которых нет в таблице выше.

**Конфликт богов — проверить, не выдумывать:** у владелицы авторская раскладка

уже отдано другой планете, **не назначать его второй раз молча** — вынести
вопрос владелице отдельным пунктом отчёта.

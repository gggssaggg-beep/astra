# astra-engine — как пользоваться

Расчётное ядро Astra на Java: положения объектов, знаки и градусы, дома,
аспекты как интервалы. Западная школа. Сети не требует, всё считается на месте.

Прежде чем подключать — прочитайте раздел «Лицензия» в
[README](../README.md#️-лицензия--решить-до-подключения). Ограничение реальное
и решается до кода, а не после.

---

## 1. Подключение

Библиотека собирается Gradle и кладётся в `build/libs/astra-engine-0.1.0.jar`.
Снаружи ей нужно ровно одно: **каталог файлов эфемерид**.

### Gradle

```groovy
dependencies {
    implementation files('libs/astra-engine-0.1.0.jar')
}
```

Больше ничего добавлять не нужно: эфемериды уже внутри jar — порт Swiss
Ephemeris собирается из исходников самой библиотеки (почему так, а не
зависимостью, — в [THIRD-PARTY.md](../THIRD-PARTY.md)).

### Файлы эфемерид — их надо взять с собой

Каталог `ephe/` (около 2,5 МБ) лежит в репозитории Astra РЯДОМ с этой папкой, а
не внутри неё. **Передавая библиотеку в другой проект, копируйте его вместе с
ней** — без файлов эфемерид не посчитается ничего. Если положить `ephe/` прямо
внутрь `astra-engine/`, сборка найдёт его сама и папка станет полностью
автономной.

Дальше — положите каталог рядом с приложением и передайте путь в конструктор. Без него библиотека работать не
будет: самодельных формул в проекте нет принципиально, всё считает Swiss
Ephemeris по своим файлам.

На Android каталог кладут в `assets/ephe` и один раз распаковывают в
`context.getFilesDir()`, потому что порт читает файлы обычным `File`, а не
через `AssetManager`.

## 2. Первый вызов

```java
import ru.svcode.astra.*;
import java.time.Instant;
import java.util.List;

try (var eph = new SwissEphemeris("/data/ephe")) {

    // где сейчас Солнце и Луна
    var pos = eph.positions(Instant.now(), List.of("Солнце", "Луна"));
    for (var p : pos) {
        System.out.println(p.name() + " — " + Zodiac.format(p.lon())
                + (p.retro() ? " ℞" : ""));
    }
    // Солнце — 17°23′ Лев
    // Луна — 4°58′ Стрелец
}
```

`SwissEphemeris` реализует `AutoCloseable` — закрывайте его (try-with-resources
или явный `close()`), иначе порт держит открытыми файлы эфемерид.

Объект тяжёлый: создавайте **один на приложение**, а не на каждый расчёт.
Потокобезопасным его считать нельзя — либо один поток, либо свой экземпляр на
поток.

## 3. Что можно спросить

### Положения объектов

```java
List<Ephemeris.BodyPosition> pos = eph.positions(utc, names);
```

Имена объектов — русские, как во всём проекте: `Солнце`, `Луна`, `Меркурий`,
`Венера`, `Марс`, `Юпитер`, `Сатурн`, `Уран`, `Нептун`, `Раху`, `Кету`.
Список в каноническом порядке — `Constants.BODY_ORDER` (плюс `Constants.MOON`
и `Constants.KETU`, они обрабатываются особо).

В ответе: долгота, знак, градус внутри знака, скорость (°/сут) и признак
ретроградности. **Кету считается как узел плюс 180°** — отдельного тела для
него в эфемеридах нет.

### Знак и градус

```java
Zodiac.Sign s = Zodiac.signOf(300.4);   // Водолей, 0.4°
String human = Zodiac.format(300.4);    // «0°24′ Водолей»
```

Правило проекта: астрологу показывают знак и градус, а не сырую долготу.

### Дома

```java
var h = eph.houses(eph.toJD(birthUtc), 55.7558, 37.6173, "placidus");
if (h != null) {
    double asc = h.asc(), mc = h.mc();
    double firstHouse = h.cusps()[0];
}
```

Системы: `horizontal` (наш дефолт), `placidus`, `koch`, `porphyry`,
`regiomontanus`, `campanus`, `equalAsc`, `equalMC`, `wholeSign`.

`null` означает, что система не считается для этих координат — так бывает у
Плацидуса и Коха в заполярье. Это не ошибка, это свойство самих систем:
обработайте `null`, а не считайте его сбоем.

### Аспекты суток

```java
Aspects.DayAspects day = Aspects.aspectsOn(eph, Instant.parse("2026-08-09T00:00:00Z"));

for (var a : day.fast()) {
    System.out.printf("%s %s %s%n", a.p1(), a.symbol(), a.p2());
    System.out.println("  точно:  " + a.exactTime());
    System.out.println("  окно:   " + a.beginTime() + " → " + a.endTime());
    System.out.println("  орбис:  " + a.exactOrb() + "°");
    System.out.println(a.applying() ? "  сходится" : "  расходится");
}
```

**Главное, что надо понять про этот метод:** аспект здесь — не «событие дня», а
ИНТЕРВАЛ. `beginTime` и `endTime` — вход в орбис и выход из него; они спокойно
выходят за границы суток, и это нормально, а не ошибка. `exactTime` может быть
`null`: аспект держится весь день, но точный момент пришёлся на другие сутки.

Результат разложен на три корзины:

| корзина | что внутри | как показывать |
|---|---|---|
| `slow()` | оба объекта медленные | фон эпохи, висит неделями |
| `fast()` | всё остальное | обычные аспекты дня |
| `moon()` | всё с Луной | по часам, отсортировано по времени точного момента |

Порядок внутри корзин — не случайный и не алфавитный: сверху пары, которые
ведёт более быстрый и близкий к Солнцу объект (требование астролога). Если
выводите список как есть — порядок уже правильный.

`audit()` — предупреждения о сломанном расчёте: Меркурий дальше 28° от Солнца
или Венера дальше 48° физически невозможны. Пустой список — норма; непустой
означает, что что-то не так с эфемеридами, и показывать такую карту нельзя.

### Свой орбис

```java
var day = Aspects.aspectsOn(eph, dayStart,
        name -> name.equals("Луна") ? 3.0 : 1.0,   // орбис по объекту
        true,                                       // включать Луну
        List.of("Солнце", "Луна", "Марс"));         // только эти объекты
```

Для пары берётся **больший** из двух орбисов — так решил астролог, и это же
поведение в приложении.

### Юлианские даты

```java
double jd = eph.toJD(Instant.now());
Instant back = eph.fromJD(jd);
```

Нужны, когда зовёте `houses` или считаете что-то своё по сетке времени.

## 4. Подмена поставщика эфемерид

Вся логика выше `Ephemeris` от Swiss Ephemeris не зависит — это интерфейс из
шести методов. Если лицензия не подходит или нужен другой источник, реализуйте
его сами:

```java
public class MyEphemeris implements Ephemeris {
    public double toJD(Instant utc) { ... }
    public Instant fromJD(double jd) { ... }
    public double lon(double jd, String name) { ... }
    public double[] lonSpeed(double jd, String name) { ... }
    public List<BodyPosition> positions(Instant utc, List<String> names) { ... }
    public Houses houses(double jd, double lat, double lon, String system) { ... }
    public List<String> audit(double jd) { ... }
}
```

`Aspects`, `Zodiac`, `Angles` продолжат работать без единой правки. Только
имейте в виду: после подмены **обязательна повторная сверка золотыми файлами** —
другой источник даёт другие числа, и молча расходящиеся даты хуже, чем явная
ошибка.

## 5. Проверка правильности

В `golden/` лежат JSON, снятые с работающего JS-движка Astra. Java-тесты
читают те же файлы и сверяют числа:

```bash
cd astra-engine
gradle test
```

Пересоздать эталон (после изменений в JS-движке):

```bash
node astra-engine/tools/golden.mjs
```

Если тесты движка «пропущены», а не пройдены — не найден каталог эфемерид.
Это сделано намеренно: зелёная сборка не должна означать «проверено», когда
проверять было нечем.

## 6. Частые ошибки при подключении

**«swe_calc_ut: file not found»** — не найден каталог эфемерид. Путь в
конструкторе должен указывать на папку с файлами `.se1`, а не на архив и не на
`assets`.

**Даты уезжают на часы** — почти всегда перепутан пояс: библиотека работает
только в UTC (`Instant`). Гражданское время переводите на своей стороне через
`ZonedDateTime`, и берите **историческую** зону места рождения, а не текущее
смещение: в СССР действовал декретный час, и час разницы двигает Асцендент на
целый знак.

**Пустой список аспектов** — проверьте орбис (по умолчанию 1°, это узко) и что
объекты не отфильтрованы четвёртым параметром.

**Разные числа с приложением** — сверяйтесь не результатами, а входом: момент в
UTC, координаты (широта, потом долгота — их часто путают местами), система
домов. Ошибка почти всегда там, а не в расчёте.

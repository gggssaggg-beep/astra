## Ключевое отличие от текущего движка

Сейчас Astra считает аспекты как ИНТЕРВАЛ во времени (вход→точно→выход) для
ОДНОГО неба на момент. Натальная/синастрическая/композитная карта —
**статичный снимок** (фиксированные долготы), аспект = просто разница углов на
этот момент, без окна. Значит нужны новые «статичные» функции аспектов, не
переиспользуя транзитные `aspectsOn`/`AspectRecord` (там beginTime/endTime).

## Модель данных — «человек» (готова к домам)

Новая коллекция в `lib/db.ts` (`people`), входит в export/import и durable-save.
Поля СРАЗУ включают время и место (для домов позже), но они опциональны:

```ts
interface Person {
  id: string;
  name: string;
  birthDate: string;        // 'YYYY-MM-DD' (гражданская дата рождения)
  birthTime: string | null; // 'HH:MM' или null = время неизвестно
  birthTz: string;          // IANA пояс МЕСТА рождения (для перевода в UTC)
  place: { name: string; lat: number; lon: number } | null; // нужно для домов
  unknownTime: boolean;     // true → берём полдень (12:00), Луна/дома неточны
  createdAt: string;
}
```

- **Момент рождения (UTC)** = `zonedDayStartUTC(birthDate, birthTz)` + время
  (при `unknownTime` — 12:00 пояса рождения). Логика перевода уже есть в
  `lib/format.ts`.
- Место для домов: пока поле опционально. Ввод координат — вручную (широта/
  долгота) ИЛИ маленький встроенный список городов (оффлайн; геокодинг по сети
  НЕЛЬЗЯ). Для v1 без домов место можно не заполнять.

## Расчёт (новый модуль, напр. `engine/relationship.ts` или `lib/charts.ts`)

Позиции натала = уже существующий `engine.positions(instantUTC)` — движок считает
на любой момент, менять его НЕ надо.

- `natalPositions(engine, person): BodyPosition[]` — обёртка (момент из person).
- **Синастрия** — межаспекты между двумя наборами:
  `synastryAspects(posA, posB, orbOf): CrossAspect[]` — для КАЖДОЙ пары
  (a из A) × (b из B), включая одноимённые (A.Солнце–B.Луна и т.п.), проверить
  разницу долгот против углов ASPECTS; орбис пары — БОЛЬШИЙ из orbOf(a),orbOf(b).
  `CrossAspect = { a: string; b: string; aspect; symbol; orb; tone }` (без
  времени — снимок). Порядок вывода — по удалённости от Солнца, как в транзитах.
- **Композит** — карта средних точек:
  `compositeChart(posA, posB): BodyPosition[]` — для каждого объекта КРУГОВАЯ
  средняя точка долгот (по КОРОТКОЙ дуге: `mid = normalize(lonA + signedDelta/2)`,
  где signedDelta = кратчайшая разница lonB−lonA в (−180,180]). Затем
  `staticAspects(posMid, orbOf): StaticAspect[]` — аспекты ВНУТРИ одного набора
  (пары i<j, разница углов vs ASPECTS). Тот же StaticAspect используем и для
  «просто натальной карты» одного человека, если понадобится.

Тон аспекта (гармоничный/напряжённый/нейтральный) — из существующего
`aspectTone` (lib/format.ts).

## UI

Вход: в Библиотеке новый пункт «Совмещённые карты» (или отдельная шторка).
- **Люди**: список + форма добавить/править/удалить (имя, дата, время +

- **Карта**: выбрать двух людей → переключатель **Синастрия / Композит** →
  - колесо: для синастрии ДВА кольца (внешнее — B, внутреннее — A) + линии

    (двойное кольцо + набор линий по CrossAspect); переиспользовать signIcons,

    (глиф-аспект-глиф, имена участников, орбис; без вход/точно/выход). Можно

- Позиции — в знаке+градусе (`fmtPos`), не сырой долготой.

## КОМПОЗИТ v1 — проект (Fable, 2026-07-27; размораживание Ф2)

Смысл для UI: композит — ОДНА карта, построенная из двух: каждая точка —
круговая середина дуги между одноимёнными планетами двоих
(`circularMidpoint`, короткая дуга — НЕ арифметическое среднее). Читается как
карта САМИХ отношений («характер союза»), не характер людей. У точек композита
нет скорости и ретро-статуса, дома не считаются.

Движок ГОТОВ и оттестирован (`engine/static.ts`: `compositeChart`,
`staticAspects`, тесты в `app/test/static.mjs`, включая переход через 0° Овна
и детерминированную оппозицию). Менять движок НЕЛЬЗЯ — только UI/промпт/тексты.

### Ф2а — режим «Композит» в хабе карт (Sonnet-агент, механика)
Пятый режим в `ChartsSheet.svelte` (`Mode` + MODES: label «Композит», need 2,
hint «общая карта пары — середины между вашими планетами»). Точки правок:
- `posMid = compositeChart(posA, posB)`; `compAsp = staticAspects(posMid, orbOf)`.
  slowOnly-фильтр людей наследуется сам (compositeChart сопоставляет по имени —
  пересечение наборов).
- Колесо: ОДНО кольцо как натал, БЕЗ домов (дома A к композиту не относятся —
  housesA НЕ передавать). Легенда: «композит A + B — середины планет».
- Список аспектов: статичные карточки как у натала (`toggleDetail(a, null,
  null)` — без владельцев, StaticAspectRow без окон). Над списком hint:
  «Композит — карта самих отношений: аспекты читаются как характер союза».
- Детальная шторка: работает как натальная (pairLore уже вычищен от «парного»
  языка). Спец-тексты — Ф2б, в v1 не трогать.
- Положения: в свёрнутом блоке «Позиции» — группы A, B и «Композит» (posMid).
- Прогноз транзитов К КОМПОЗИТУ: точки фиксированы → готовый механизм
  `forecastTransits` работает; `forecastTargets` для режима — `[{ owner:
  'композит', pos: posMid }]`. `gotoHit`: натальный набор для деталей = posMid.
  «Когда ещё» (detailAnchor) при этом честно ищет транзит к градусу композита.
- Промпт: kind `'composite'` (расширить union в `aiPrompt.ts`); people = оба
  человека (данные рождения) + третий блок «Композит A + B» с positions/raw;
  аспекты через aspLine (вес аспектов работает автоматически); extra объясняет,
  что такое композит и что домов/скоростей у него нет.
- Заметки: `chartSource` (lib/journal.ts) → `«A+B композит»` (без даты — карта
  вне времени, как натал).
- Фигуры: `chartFigures('natal', posMid, …)` — классические фигуры на карте
  середин (маппинг режима в вызове, lib не менять).
- Предупреждения unknownTime и строки «род. …» — показывать ОБОИХ (условия
  `synastry || triple` дополнить composite).
- restore-логика (`need`) и `activeKeys` — учесть новый режим.
ПРОВЕРКА UI: пятая кнопка в seg-ряду режимов — убедиться, что ряд не ломается
на телефоне (допустим перенос на 2 строки); визуальную приёмку делает владелица.

### Ф2б — тексты (Sonnet-партия, потом)
- `COMPOSITE_FEEL[aspect]` — рамка-добавка «в композите …» к текстам пары
  (по образцу SYNASTRY_FEEL/TRANSIT_FEEL: ДОБАВКА, не переписывание корпуса —
  урок аудита транзитных текстов).
- Заголовок блока в детальной шторке для композита («У ваших отношений»),
  placeholder заметки «Как проявилось в союзе…».

### Ф2в — ОТДЕЛЬНОЕ решение владелицы (не делать без команды)
- Режим «Транзит + композит» с внешним кольцом и скрабом — это ШЕСТАЯ кнопка
  (плотность seg-ряда!). Пока транзиты к композиту закрыты блоком прогноза.
- Двойные попадания транзита в композит + оба натала (перекрёстная активация
  трёх карт) — если Ф2в случится.

### НЕ делаем (зафиксировано)
- Дома композита: методики (midpoint-houses / composite Asc) спорные, требуют
  точного времени И места обоих; базы текстов под них нет. Без запроса — нет.
- Композит больше чем для двух людей — нет такого в астрологии, не выдумывать.
